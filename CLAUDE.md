# Dante: notes for Claude

Native macOS IDE in Swift 6 / SwiftUI, built with SwiftPM (no Xcode project). Design reference: https://claude.ai/artifact/KFxwBAj14jL7w1MHNcc5Pi (generated by `design/generate_screens.py`).

## Commands

- Build: `swift build`
- Test: `swift test` (Swift Testing: `import Testing`, `@Test`, `#expect`)
- Large-repo timings: `DANTE_BENCH=1 swift test -c release -Xswiftc -enable-testing --filter LargeRepoBenchmark` (a generated 50k-file repo; prints each whole-project pass)
- App bundle: `scripts/bundle.sh [debug] [--open]` → `build/Dante.app` (bundle id `dev.dante.ide`)
- Release: `scripts/release.sh <version>` → `build/Dante-<version>.dmg` (signs and notarises only when `DEVELOPER_ID` and `NOTARY_PROFILE` are set; otherwise ad-hoc). Build anything you publish from a checkout outside the home folder (`git worktree add /tmp/dante-release <tag>`): SwiftPM writes the build path, and so the user name, into the binary. The icon is drawn by `swift scripts/make_icon.swift` into `Resources/AppIcon.icns`.
- Open a folder on launch: `open build/Dante.app --args "$PWD"` (files after the folder open in tabs) (AppDelegate turns off `NSTreatUnknownArgumentsAsOpen`; otherwise AppKit treats the path as an open-file event and SwiftUI makes no window)

## Modules

- `DanteOpen` (Foundation only): `OpenRequest` parses the `dante` command's arguments (`file:line`, `-n`) into a `dante://open?path=…&line=…` URL and reads it back (file URLs too, from Finder and the Dock); `OpenTarget.plan` sends each folder to one window and each file to a requested folder, an open project, or its nearest `.git`/`.dante` folder. `DanteCLI` is the `dante-cli` product, bundled as `Contents/Resources/bin/dante`; it runs `open -a <its app> <url>`. In the app, `Opener` (from `RootView.onOpenURL`, with `handlesExternalEvents` so existing windows take the event) reuses the window with the folder, then a launch-screen window, then asks `openWindow` and queues the target for the new window's `onAppear`. `CommandLineTool` (DanteKit/System) gives Settings → Tools the `ln -sf` to type into the terminal.

- `DanteKit`: UI-free models. `@MainActor @Observable` classes, value types elsewhere. Must not import SwiftUI views.
- Fonts: Geist and Geist Mono (OFL, `DanteEditor/Resources/Fonts`) are registered at launch by `DanteFonts`. Use `.font(.dante(size:weight:design:))` in views, never `.system(size:)`, and `DanteFonts.mono`/`sans` for AppKit; both fall back to the system fonts when `Preferences.usesGeist` is off.
- `DanteEditor`: the AppKit editor (`CodeEditorView` wraps a TextKit 2 `NSTextView`). Highlighters sit behind the `Highlighter` protocol: `TreeSitterHighlighter` (SwiftTreeSitter plus grammar packages for Swift, Python, JS, TS, Go, Rust and JSON, queries read from their resource bundles) with `RegexHighlighter` as the fallback. Keep grammar packages on tags that list `scanner.c` explicitly. Tokens are computed off the main thread. `Completion.swift` draws the completion list inside the editor's scroll view (child windows don't show in window captures); keys reach it through `doCommandBy`. Text changed outside the editor (reload, rename, format) is applied as one undoable edit of the differing range. `revealRange` scrolls with `CodeEditorView.center`, which lays out TextKit 2 up to the range and centres it without scrolling the gutter away.
- `DanteKit/Claude`: talks to Claude Code with `claude --input-format stream-json --output-format stream-json --permission-prompt-tool stdio` (the Agent SDK's wire protocol). `ClaudeEvent` parses output lines, `ClaudeInput` builds stdin messages, `ClaudeSession` keeps the transcript, and `ProposedChange` turns Edit/MultiEdit/Write calls into diffs. `Attachment` turns files into user-message content blocks (images resized to 1568px, PDFs as `document` blocks, Word/RTF/HTML via `textutil`, other binaries by path); `Session.claudeAttachments` holds them until the next `askClaude`. `InlineEdit` is ⌘I in the editor: the selection widened to whole lines, a prompt with the surrounding code, and the reply cleaned of fences; `InlineEditModel` (DanteApp) holds the proposal until accepted. `ClaudeSession.asksFirst` appends `ClaudeBrief.clarifyingQuestions` to the system prompt; AskUserQuestion calls arrive as permission requests and are answered with `answer(_:answers:)`, which returns the input with `answers` filled in. `ClaudeHistory` reads earlier conversations back from Claude Code's transcripts for the panel's history popover (`resume(conversation:items:)` continues one). Transcripts reach hundreds of MB, so `TranscriptScan` reads them as bytes (memchr/memmem); a line's own `"type"` often comes after `message`, so use `topLevelType`, never the first match. `ClaudeUsage` estimates the current five-hour window and the week from every local transcript (deduped by message id); `ClaudeAccount` keeps only the plan from `claude auth status`. Never read Claude Code's credentials or call its usage endpoint. `result.total_cost_usd` is a running total per process, not per turn. `TokenUsage` on assistant events drives the context meter in `ClaudeFooter`; `compact()` sends `/compact`. `onAttention` fires when a turn finishes or a tool waits for approval; `Session.notifyClaude` posts a notification when `Preferences.notifiesOnClaude` is on and Dante isn't active. Each turn keeps a `TurnCheckpoint` (`ClaudeSession.checkpoints`, keyed by the user item's id): `approve()` saves a file's text before Claude Code applies the edit, and `undoTurn` writes the originals back (deleting files the turn created) and tells Claude on the next message. Bash side effects aren't undone. `applyAll(restOfTurn:)` approves the waiting edits and, with `restOfTurn`, every edit until the turn ends (`ApplyAllBar` over the composer). `ComposerToken` finds the `@file` or `/command` being typed; `ComposerCommand` lists the built-in commands and one per skill; mentioned files are named to Claude in the message's context. `ClaudeSetup` backs the Claude area (`ClaudeAreaView`): `ClaudeSkills` (SKILL.md front matter in `.claude/skills` and `~/.claude/skills`, `suggestions` from the project's files with a draft prompt each, a fortnightly `reviewDue`), `ClaudeMemoryFile` (CLAUDE.md files and their per-message token cost), `MCPServer.parse` (`claude mcp list`), `ClaudePlugin.parse` (`claude plugin list --json [--available]`, read leniently) and `ClaudePermissions`. `Session.workOn(task)` (board menu and palette) checks out the task's branch and continues its conversation; the branch is kept on the task as `branch:` (`TaskBoard.setField`); the conversation id (from `ClaudeSession.onConversationStarted`) is per Mac in `TaskConversations`, since session ids mean nothing in the repo. Child processes must not inherit `CLAUDECODE`, or Claude Code refuses to start as a nested session. `ClaudeRules` reads `claude:` from `project.yaml`: `never` paths go to Claude Code as `--settings` deny rules and are also refused in `can_use_tool`; `flag` and out-of-`propose` edits get a `ruleNote` on the diff.
- `DanteKit/Plan`: `LifecycleTemplate` (app, infra, apple, data: phases, starting checklists, detection from file paths; `Workspace.setUp` writes `.dante/` from one). `ProjectProfile.detect` guesses stack, template, stage and secrets for a project without a spec; `ProjectSetupRequest` builds the prompt from the parts ticked in `SetupSheet`, which `Session.offerSetup` shows on open. `.dante/tasks.yaml` (`TaskBoard`, via Yams; read leniently: `status:`/`notes:`/`name:` and open/closed/wip spellings, unknown fields kept in `extra`, and `TaskFile.explain` turns a decoding error into a sentence; a task's `spec:` is looked for in `.dante/` and then the repo, through `specURL`) and `.dante/phases/<phase>.md` (`PhaseDoc`, plain markdown checklists). `Workspace.reloadSpec()` re-reads all of `.dante/`; the file watcher calls it on any change there. Edits to `project.yaml` are made line by line (`Lifecycle.settingCurrent`) so comments survive.
- `DanteKit/LSP`: for a remote project, `LanguageServices` starts a server on the host when the host has it (`LanguageServer.hostProbeScript`, run once per window by `Session+Remote`, results in `RemoteRegistry.hostServers`; `moveToHost` restarts ones already running here), and `LSPClient` maps URIs both ways with `LSPURIMap`. `LSPFraming` (Content-Length JSON-RPC), `LSPClient` (one server process: initialize, full-text didOpen/didChange, publishDiagnostics, definition, completion, references, rename, formatting, and `workspace/didChangeWatchedFiles` for files changed on disk but not open), `LanguageServices` (per window, lazily starts the server in `LanguageServer.all` for a file's language; edits are debounced). `Symbols` has `CodeSymbol` (documentSymbol/workspace symbol results) and `DeclarationScanner` (regex declarations per language, for files and the whole project when no server helps). `LSPEdits` holds completion items, `Snippet.expand`, `LSPTextEdit.apply` (skips repeated edits) and `LSPWorkspaceEdit`. sourcekit-lsp reports index references as empty ranges and renames only the current file from top-level code, so `LSPWorkspaceEdit.include` adds the missing references. Positions are UTF-16, like NSString; convert many with `LineIndex`. `Problems.files` groups `LanguageServices.allDiagnostics` by file for the sidebar's Problems tab (`ProblemsPanel`).
- `DanteKit/Search`: `ProjectSearch` scans the workspace's file index (no ripgrep dependency) with NSRegularExpression, using open dirty documents' text; columns are UTF-16. `ProjectReplace` re-matches the current text and replaces matches chosen by id (`line:column`). `SearchState` (DanteApp) debounces and keeps results per window; `Session+Search` does the replacing.
- `DanteKit/Project/GitRepository`: `GitStatus` (porcelain v1 `-z`), `GitBranch` (for-each-ref), `UnifiedDiff`, and the commands behind the Changes panel. Network commands never prompt (`GIT_TERMINAL_PROMPT=0`, ssh BatchMode); a `Failure` that needs credentials carries the `terminalCommand` to run instead. `ClaudeQuick` is a one-shot `claude -p --tools ""` for small jobs such as `CommitMessage`; `CommitMessage.read` splits a `WARNING:` line (or a reply that reads like prose) off the message, and `SecretScan` checks the diff's added lines first, so both commit boxes show a `CommitWarning`. `GitModel` (DanteApp, `Session.git`) is loaded from `WorkspaceView` on every revision. `GitBlame` blames the editor's text through `--contents`, so unsaved edits don't shift lines; the status bar shows the caret line's commit. Quote arguments typed into the terminal with `Shell.quote`. Merge conflicts: `MergeConflict` parses markers (diff3 bases too) and rebuilds the file from per-hunk `Choice`s, leaving unchosen hunks' markers exactly as they were; `GitRepository.diff3` re-merges the index stages with `--diff3` so `fillingBases` can add bases the working file lacks; `MergeOperation.detect` reads MERGE_HEAD, rebase-merge/ and friends (in a rebase "ours" is upstream, so `sides` names them). `ConflictView` replaces `DiffView` for conflicted files; Mark Resolved writes and stages, and Changes shows Continue/Abort while an operation is in progress. `ExplorerSelection` holds the explorer's multi-selection (Finder's click rules); Finder may hand over file reference URLs, so pass dropped and pasted URLs through `FileOperations.resolved`.
- `DanteKit/System/Shell`: `Shell.run` (drains both pipes) and `Shell.stream` (merged lines) for every external command, with the user's login-shell environment. A folder inside an open remote project's mirror runs the command on its host instead.
- `DanteKit/Remote` (docs/plans/remote-ssh.md): a remote project is a local mirror kept in step by `RemoteSync` (rsync over ssh; deletions only cross for files unchanged since the last sync, pushes only send files changed here, mass deletions are held back; the last sync's files and times are saved beside the mirror). `RemoteRegistry` maps open mirrors to hosts for `Shell`, `ClaudeSession` (runs `claude` on the host; `mirrorPaths`/`hostPaths` map tool-call paths) and the terminal; it also remembers known mirrors per Mac. `SSH` builds command lines (`BatchMode`, a shared `ControlMaster` started by `connect` with its output in a file, never a pipe); `DANTE_SSH` swaps in a stand-in, which the tests use to sync a local folder. `Session+Remote` attaches a sync when a mirror opens; the debugger is off for remote projects. `Shell` sends `extra` environment (passwords) to a host on stdin (`readingEnvironment`), never on the ssh command line. Compose and database clients run on the host (`DatabaseClient.route(projectRoot:)` can't check the host for a client, so it picks the compose service or the bare client name); running services' ports are forwarded here with `SSH.forward` (`RemoteSync.forwarded`/`unforwarded`), and the Env area skips this Mac's port checks. The host's Claude transcripts are copied to `RemoteProject.transcriptsURL` (`RemoteSync.pullTranscripts`, on opening and after each turn), where `ClaudeTranscripts.folder` and `ClaudeUsage` find them.
- `FileIndex.scan` must only `skipDescendants()` on folders: on a file (.DS_Store) it skips the rest of the parent folder. Area data, one folder each in `DanteKit`: `Docs` (`MarkdownDocument`, which turns HTML blocks such as a README's centred header into images, headings and paragraphs, `Mermaid`: a parser for the flowchart, sequence and ER subset, drawn by `MermaidView` in the app rather than mermaid.js). `DocLibrary` also lists PDFs, images and Word files, but only under docs/, documentation/ and .dante/; elsewhere they're app assets, `Testing` (`TestCommand`, whose `only(_:)` (and `only(written:)` for ticked tests) narrows the detected runner to some tests, `TestOutputParser`, xUnit; `TestInventory` reads tests from the code and sorts them into categories, `TestGaps` finds declarations no test names; `TestImpact` picks the tests for changed files (the Tests header's Run changed), and after a narrowed run the header's main button repeats it; `TestHistory` finds flaky tests in `TestRecord`s), `Environments` (`ComposeFile`, `ContainerState`, `ComposeDiagnosis`: notes on why services aren't up, from health check output and `ListeningPort`s via lsof; `PortCheck`/`PortHolder` add the command line, working directory and uptime, and stop a holder; `PortConflict`; `ComposeEditing.republishing` moves one host port; `LogLine`/`LogFilter` parse and filter compose log lines for `ComposeLogsPanel`; `LogLine.request` is found once at parse time so hiding health checks stays cheap), `Data` (`DataDetector`, `DatabaseConnection`, `SQLScript`, `DatabaseClient` runs SQL through psql/mysql/sqlite3 with one argument per statement and a marker after each, `SchemaQueries`, `QueryPlan` (EXPLAIN output → `PlanFinding`s with index suggestions), `MigrationPreview` (DDL → `SchemaChange`s checked against the schema; reads with `SQLToken`/`SQLTokenReader`), `NewDatabasePlan`/`ComposeEditing`/`EnvFile`, `ConnectionStore` (per Mac, not in the repo) and `DatabasePasswords` (Keychain)), `Map` (`ArchitectureGraph`: Go projects from go.mod and imports via `goModules`, otherwise `folders()`; `SystemMap`, the default Map view: lanes of clients (frontends and their screens), API route groups, backend parts, data stores and outside services, linked by fetch paths, route owners, imports and hosts; data packages that only store a host don't count as calling it; search file bodies with `SystemMap.has` (memmem on native UTF-8) and keep regexes static, since `String.contains` and Swift `Regex` literals made a 6,000-file repo take a minute; tables come from `CREATE TABLE` in the repo (never a live database) with links from packages whose queries name them; routes named like webhooks link from the outside service their handler mentions; `Part.env` holds environment variable names from code and compose, `isSecret` flags likely secrets; `mermaid()`/`exporting(into:)` write a marked section of `.dante/architecture.md`; `isTest` covers test folders and class-style names (`ParserTests.swift`), route examples in comments are skipped, a file naming six or more services counts as a catalogue rather than a caller, and without a detected database only `.sql` files give tables; `MapView` keeps its last build per window in `Session.mapCache` (and Ship its last load in `shipCache`); `coverage(_:)` sums a `CoverageReport` (Testing: lcov, Go cover profiles, Cobertura, matched to repo files by the longest shared path tail) per part), `Release` (`ReleaseDraft`, `CIRun`, `PullRequest`: `TaskBranch`, `PullRequestDraft`, `GitHub` via `gh`; `BranchReview` asks Claude to review the branch diff in the Finish sheet and parses `- [blocker|issue|nit] file:line — text` findings), `Operate` (`HealthMonitor`, `ErrorDigest`, `LogWatch`, `Alarms`: `AlarmSource` from `operate.alarms`, CloudWatch and command-JSON parsers, `AlarmMonitor` polled per window from `Session+Alarms`; tasks keep the alarm's id in `alarm:`), `Timeline` (`TimelineEvent`s from git log, `ClaudeTranscripts` in `~/.claude/projects/<encoded path>`, `TestRecord` history per Mac, CI runs; `TestRun.onFinish` records each run). `Project/ProjectVisit` records HEAD and task states per Mac when a project closes; `SinceLastVisit` compares on the next open for Home. `Project/ProjectInfo` reads the rest of `project.yaml` (`test:`, `operate:`). Keep parsers pure and tested.
- Settings live in the window (`SettingsArea`, the `.settings` area; ⌘, opens it): appearance, editor, files, Claude, tools (`Tool`/`ToolStatus` in `System/Toolchain`: versions and install commands, typed into the terminal but never run), and this project (move `.dante` to the Trash, set up again, forget saved connections). With no project open, ⌘, shows `SettingsView` as a sheet.
- Menu shortcuts come from `Shortcuts` (DanteKit/Settings: `KeyBinding`, the command list with defaults, overrides in user defaults); menus use `.shortcut("id")` and hints use `Shortcuts.label`, never a literal key. SwiftUI doesn't rebuild menus it has made, so `MenuShortcuts` (on `Shortcuts.onChange`) sets the changed `NSMenuItem` directly; its own items refuse the shortcut they were built with, so a reset to a default can need a restart (`needsRestart`, noted in Settings). Settings → Keyboard records them; Settings → Languages edits `LanguageServerOptions` per server (off, command, JSON sent as initializationOptions and answering `workspace/configuration`), and `LanguageServices.restart` applies them.
- `DanteKit/Settings/Preferences`: everything in the Settings window except theme and font size (`ThemeStore`), in user defaults; `Preferences.shared` is read directly by views and `Session`. `Session.save` tidies whitespace and writes now; `saveFormatting` (⌘S, Save All) formats first when asked; auto-save writes without tidying.
- Files that aren't text open in a viewer tab: `FileKind` (from the extension, else the bytes) on `EditorDocument.kind`; `FileViewer` shows PDFs, images, Word, media and Quick Look types. A viewer's `text` is empty and `save()` refuses to write it.
- `DanteKit/Debug`: `DebugAdapter` (Go: `dlv dap --listen 127.0.0.1:0`, connected over TCP once it prints its address; Python: `debugpy.adapter` over stdio), `DAPConnection` (the process and channel, LSP framing; `DANTE_DAP_TRACE=1` prints traffic) and `DebugSession` (initialize, launch without waiting, breakpoints after `initialized`, then configurationDone). Paths go through `DebugSession.canonical` (realpath): Go refuses a module under `/var` when it's really `/private/var`. `Session+Debug` keeps 1-based breakpoints per file (saved per project on this Mac) and the run; `CodeEditorView` takes zero-based `breakpoints`/`executionLine`, and `LineNumberRuler` draws and toggles them. `BreakpointShift` moves them with each edit, through `CodeEditorView.onEdit` (set only when the file has breakpoints). Its `accessibilityPerformPress` is a no-op, because NSRulerView's own opens a tab-stop sheet. F-keys work in `Shortcuts` (`KeyBinding` with no modifiers).
- Split editor: `Workspace.split` holds the unfocused pane's document; `activeDocument` is always the focused pane's, so everything that acts on "the open file" follows focus. `CodeEditorView.onFocus` reports clicks into a pane and `takesFocus` moves focus when it flips on.
- Presence (`DanteKit/Presence`, `DanteApp/Views/Presence`): the menu bar orb. `Presence.combine` turns every window's `PresenceSource` (from `Session.presenceSource`) into one `PresenceMood`, most urgent first; `PresenceTracker` shows `done` for a moment after a turn; `OrbStyle` holds each mood's palette, energy, aura and lightning (idle cycles `idleForms`). `PresenceController` owns the status item and its popover (`PresencePanel`), re-reads through `withObservationTracking`, and feeds the pointer to every `OrbView` it has attached. `OrbView` is an MTKView drawing `OrbShader` (Metal source compiled at runtime, since SwiftPM doesn't build .metal files); it eases between styles, blinks, follows the pointer and pauses when occluded. `DANTE_ORB_SNAPSHOTS=<folder>` writes every mood as PNGs and quits.
- `DanteApp`: the SwiftUI app. `Session` holds per-window state, including terminal tabs and back/forward history (`Session.Place` in a `NavigationHistory`, recorded from `onChange(of: session.place)`); `ThemeStore` is app-wide. Area screens live in `Views/Areas` and are built from the shared pieces in `AreaPage.swift` (`AreaPage`, `Card`, `RowList`, `EmptyState`, `CardGrid`, `Chip`, `LinkButton`). Views reload with `.task(id: workspace.revision)`.

## Conventions

- Colours come only from `Theme` tokens (`@Environment(\.theme)`), never literals in views. All three themes (Dark, Light, Paper) must look right.
- The window's system title bar is hidden; `TitleBar` draws its own and leaves room for the traffic lights.
- Menu commands reach the window's state via `@FocusedValue(\.session)`.
- `Section` is SwiftUI's; the workspace's areas are `Session.Area`.
- Dante plans itself: real tasks live in `.dante/tasks.yaml`. Move a task's state when you finish it.
- Verify UI changes by running the bundled app, not just by compiling.
