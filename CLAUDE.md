# Dante: notes for Claude

Native macOS IDE in Swift 6 / SwiftUI, built with SwiftPM (no Xcode project). Design reference: https://claude.ai/artifact/KFxwBAj14jL7w1MHNcc5Pi (generated by `design/generate_screens.py`).

## Commands

- Build: `swift build`
- Test: `swift test` (Swift Testing: `import Testing`, `@Test`, `#expect`)
- App bundle: `scripts/bundle.sh [debug] [--open]` → `build/Dante.app` (bundle id `dev.dante.ide`)
- Open a folder on launch: `open build/Dante.app --args "$PWD"` (files after the folder open in tabs) (AppDelegate turns off `NSTreatUnknownArgumentsAsOpen`; otherwise AppKit treats the path as an open-file event and SwiftUI makes no window)

## Modules

- `DanteKit`: UI-free models. `@MainActor @Observable` classes, value types elsewhere. Must not import SwiftUI views.
- `DanteEditor`: the AppKit editor (`CodeEditorView` wraps a TextKit 2 `NSTextView`). Highlighters sit behind the `Highlighter` protocol: `TreeSitterHighlighter` (SwiftTreeSitter plus grammar packages for Swift, Python, JS, TS, Go, Rust and JSON, queries read from their resource bundles) with `RegexHighlighter` as the fallback. Keep grammar packages on tags that list `scanner.c` explicitly. Tokens are computed off the main thread. `Completion.swift` draws the completion list inside the editor's scroll view (child windows don't show in window captures); keys reach it through `doCommandBy`. Text changed outside the editor (reload, rename, format) is applied as one undoable edit of the differing range.
- `DanteKit/Claude`: talks to Claude Code with `claude --input-format stream-json --output-format stream-json --permission-prompt-tool stdio` (the Agent SDK's wire protocol). `ClaudeEvent` parses output lines, `ClaudeInput` builds stdin messages, `ClaudeSession` keeps the transcript, and `ProposedChange` turns Edit/MultiEdit/Write calls into diffs. `Attachment` turns files into user-message content blocks (images resized to 1568px, PDFs as `document` blocks, Word/RTF/HTML via `textutil`, other binaries by path); `Session.claudeAttachments` holds them until the next `askClaude`. `InlineEdit` is ⌘I in the editor: the selection widened to whole lines, a prompt with the surrounding code, and the reply cleaned of fences; `InlineEditModel` (DanteApp) holds the proposal until accepted. `ClaudeSession.asksFirst` appends `ClaudeBrief.clarifyingQuestions` to the system prompt; AskUserQuestion calls arrive as permission requests and are answered with `answer(_:answers:)`, which returns the input with `answers` filled in. Child processes must not inherit `CLAUDECODE`, or Claude Code refuses to start as a nested session. `ClaudeRules` reads `claude:` from `project.yaml`: `never` paths go to Claude Code as `--settings` deny rules and are also refused in `can_use_tool`; `flag` and out-of-`propose` edits get a `ruleNote` on the diff.
- `DanteKit/Plan`: `LifecycleTemplate` (app, infra, apple, data: phases, starting checklists, detection from file paths; `Workspace.setUp` writes `.dante/` from one). `ProjectProfile.detect` guesses stack, template, stage and secrets for a project without a spec; `ProjectSetupRequest` builds the prompt from the parts ticked in `SetupSheet`, which `Session.offerSetup` shows on open. `.dante/tasks.yaml` (`TaskBoard`, via Yams) and `.dante/phases/<phase>.md` (`PhaseDoc`, plain markdown checklists). `Workspace.reloadSpec()` re-reads all of `.dante/`; the file watcher calls it on any change there. Edits to `project.yaml` are made line by line (`Lifecycle.settingCurrent`) so comments survive.
- `DanteKit/LSP`: `LSPFraming` (Content-Length JSON-RPC), `LSPClient` (one server process: initialize, full-text didOpen/didChange, publishDiagnostics, definition, completion, references, rename, formatting, and `workspace/didChangeWatchedFiles` for files changed on disk but not open), `LanguageServices` (per window, lazily starts the server in `LanguageServer.all` for a file's language; edits are debounced). `LSPEdits` holds completion items, `Snippet.expand`, `LSPTextEdit.apply` (skips repeated edits) and `LSPWorkspaceEdit`. sourcekit-lsp reports index references as empty ranges and renames only the current file from top-level code, so `LSPWorkspaceEdit.include` adds the missing references. Positions are UTF-16, like NSString; convert many with `LineIndex`.
- `DanteKit/Search`: `ProjectSearch` scans the workspace's file index (no ripgrep dependency) with NSRegularExpression, using open dirty documents' text; columns are UTF-16. `ProjectReplace` re-matches the current text and replaces matches chosen by id (`line:column`). `SearchState` (DanteApp) debounces and keeps results per window; `Session+Search` does the replacing.
- `DanteKit/Project/GitRepository`: `GitStatus` (porcelain v1 `-z`), `GitBranch` (for-each-ref), `UnifiedDiff`, and the commands behind the Changes panel. Network commands never prompt (`GIT_TERMINAL_PROMPT=0`, ssh BatchMode); a `Failure` that needs credentials carries the `terminalCommand` to run instead. `ClaudeQuick` is a one-shot `claude -p --tools ""` for small jobs such as `CommitMessage`. `GitModel` (DanteApp, `Session.git`) is loaded from `WorkspaceView` on every revision.
- `DanteKit/System/Shell`: `Shell.run` (drains both pipes) and `Shell.stream` (merged lines) for every external command, with the user's login-shell environment.
- Area data, one folder each in `DanteKit`: `Docs` (`MarkdownDocument`, `Mermaid`: a parser for the flowchart, sequence and ER subset, drawn by `MermaidView` in the app rather than mermaid.js). `DocLibrary` also lists PDFs, images and Word files, but only under docs/, documentation/ and .dante/; elsewhere they're app assets, `Testing` (`TestCommand`, `TestOutputParser`, xUnit), `Environments` (`ComposeFile`, `ContainerState`), `Data` (`DataDetector`, `DatabaseConnection`, `SQLScript`, `DatabaseClient` runs SQL through psql/mysql/sqlite3 with one argument per statement and a marker after each, `SchemaQueries`, `QueryPlan` (EXPLAIN output → `PlanFinding`s with index suggestions), `MigrationPreview` (DDL → `SchemaChange`s checked against the schema; reads with `SQLToken`/`SQLTokenReader`), `NewDatabasePlan`/`ComposeEditing`/`EnvFile`, `ConnectionStore` (per Mac, not in the repo) and `DatabasePasswords` (Keychain)), `Map` (`ArchitectureGraph`), `Release` (`ReleaseDraft`, `CIRun`, `PullRequest`: `TaskBranch`, `PullRequestDraft`, `GitHub` via `gh`), `Operate` (`HealthMonitor`, `ErrorDigest`, `LogWatch`). `Project/ProjectVisit` records HEAD and task states per Mac when a project closes; `SinceLastVisit` compares on the next open for Home. `Project/ProjectInfo` reads the rest of `project.yaml` (`test:`, `operate:`). Keep parsers pure and tested.
- `DanteKit/Settings/Preferences`: everything in the Settings window except theme and font size (`ThemeStore`), in user defaults; `Preferences.shared` is read directly by views and `Session`. `Session.save` tidies whitespace and writes now; `saveFormatting` (⌘S, Save All) formats first when asked; auto-save writes without tidying.
- Split editor: `Workspace.split` holds the unfocused pane's document; `activeDocument` is always the focused pane's, so everything that acts on "the open file" follows focus. `CodeEditorView.onFocus` reports clicks into a pane and `takesFocus` moves focus when it flips on.
- `DanteApp`: the SwiftUI app. `Session` holds per-window state, including terminal tabs and back/forward history (`Session.Place` in a `NavigationHistory`, recorded from `onChange(of: session.place)`); `ThemeStore` is app-wide. Area screens live in `Views/Areas` and are built from the shared pieces in `AreaPage.swift` (`AreaPage`, `Card`, `RowList`, `EmptyState`, `CardGrid`, `Chip`, `LinkButton`). Views reload with `.task(id: workspace.revision)`.

## Conventions

- Colours come only from `Theme` tokens (`@Environment(\.theme)`), never literals in views. All three themes (Dark, Light, Paper) must look right.
- The window's system title bar is hidden; `TitleBar` draws its own and leaves room for the traffic lights.
- Menu commands reach the window's state via `@FocusedValue(\.session)`.
- `Section` is SwiftUI's; the workspace's areas are `Session.Area`.
- Dante plans itself: real tasks live in `.dante/tasks.yaml`. Move a task's state when you finish it.
- Verify UI changes by running the bundled app, not just by compiling.
